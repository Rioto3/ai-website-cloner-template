# magic-slide — L0達成計画（令和9年6月末まで）

## 目標と前提

- **目標：L0-aを、令和9年（2027年）6月末までに達成する。**
- **期間：** 2026-09-29から約39週。
- **確保できる時間：週平均8時間（確定）。** 合計で約312時間。

[SUCCESS_DEFINITION.md](SUCCESS_DEFINITION.md)の成長の曲線でいえば、A帯（敷居）を越えて、L0に届くところまでが、この計画の範囲。

## L0の定義

| 段階 | 内容 | 扱い |
|---|---|---|
| **L0-a：収益が立つ** | **発生主義で**、AdMobの推定収益が月約7ドル（約1,070円）相当になる。判定の月は6月とする | **目標にする** |
| **L0-b：現金で回収する** | 年会費相当が入金される | 支払い元の事情として整理する。目標にしない |

L0-bが遅れるのは、**支払い元（AdMob）の支払い基準額**のため。日本円のアカウントでは8,000円（米ドルは100ドル）で、確定額で判定される。L0水準の月約1,070円のペースでは、初回の入金まで約7〜8か月かかる。会計上は収益が立っているので、L0-aの達成は妨げない。推定収益は、あとで確定額との差を確認する。

## 進め方

1. **自社HP向けのWeb版を先に用意する。** コストが低く、直接の収益にはならないが、TubeClip全体として、ゲームの収益そのもの以外の意義がある。最終的には、責任を切り出してHPのプロジェクトにすることもできる。そのため、かなり安全に進められる
2. **完成した基盤を使って、次の投資を議論する。** iOSの開発者ライセンスの取得、マーケティングとカスタマーサポートの体制へのリソース配分など。これらは、他の財源活動の観点でも重要になる
3. iOS版を公開し、広告で収益を立てて、L0-aに届ける

HPは、iOS版にも必要な基盤になる。App Storeにはプライバシーポリシーとサポートのページが要り、広告のapp-ads.txtは、ストアに登録する開発者のWebサイトに置くと理解している（要確認）。

## iOS版の実装方式：React Nativeが有力

| | React Native（Expo） | Swiftで作り直す | WebViewで包む |
|---|---|---|---|
| ゲームのコード | **エンジンをそのまま使える。** 描画・操作・音・保存は作り直す | すべて作り直す | Web版をそのまま使える |
| HP版との共通化 | **1つのコードから、iOSとWebの両方を出せる見込み**（react-native-web。要検証） | 別々に作る | 共通 |
| 審査 | ネイティブアプリなので、通りやすい | ネイティブアプリなので、通りやすい | ウェブサイトを包んだだけと見られる懸念がある（要確認） |
| 広告 | react-native-google-mobile-ads。**開発ビルドが必要**（Expo Goでは動かない） | AdMobのSDK | 橋渡しが必要 |
| 工数（後述） | **中** | **大** | 中（審査のリスクあり） |

**React Nativeを第一候補にする理由：**

- **エンジンは、ブラウザに依存しない純粋なTypeScript。** アーカイブのタグ`archive/mitsumori-ip-poc`の`src/game/engine`（盤面、重力、スコア、乱数）は、ブラウザ固有の機能を使っていない。React Nativeでそのまま動く見込み
- **作り直すのは、外側の層。** アーカイブの描画（`MitsumoriGame.tsx`）はDOMとlocalStorage、音（`audio.ts`）はWebAudioに依存しているので、そのままは使えない。音は素材ファイルと`expo-audio`に置き換える
- **2Dのパズルは、React Nativeで作られた実績がある。** ドラッグにはReanimatedとGesture Handlerを使う。Skiaは、素のビューで足りなければ追加する。Skiaを入れると、バイナリが10〜15MB増える
- **HP版とiOS版で、同じコードを使える見込みがある。** 別々に作る場合より、作業が減る

**確認が必要なこと（スパイクで確かめる）：**

- 実機でのドラッグの操作感
- エンジンが、React Nativeの実行環境で動くこと
- 開発ビルドでの広告SDKの動作
- Webへの書き出しでの挙動の差

## コスト

**来年（2027年）のコストは、年会費の約1.3万円で見積もってよい。**

- Apple Developer Programは年99ドル。日本円では、Apple Developerアプリ経由で12,800円、直近の報告で12,980円。為替や税で動くので、**予備を含めて1.5万円まで**見ておくと安全
- それ以外は、基本的に0円。AdMobは無料。HPはすでにあるCloudflare Workersの枠内。Expoのビルドは、無料枠（月30回、iOSは最大15回）内か、Xcodeでのローカルビルドで足りる
- AI素材の生成やツールの課金は、含まない

## 作業量と、週8時間（312時間）との照合

**私の見積もりで、データに基づく数字ではない。** 実際の作業速度、特にAIの活用による圧縮の度合いで、大きく変わる。スパイクで較正する。

**スコープの前提：** コア（盤面、スライド、重力、消去、せり上がり、スコア、ゲームオーバー、再挑戦、ベストスコアの保存）と、広告を出す窓口（リワード広告での続行）、テーマ素材、音。**ブースター、ショップ、ガチャ、コイン、壺とダイヤは作らない。**

React Nativeの場合の内訳：

| 作業 | 時間 |
|---|---|
| スパイク（エンジン、実機、広告SDKの検証） | 10〜20時間 |
| コア、描画、操作（エンジンを流用） | 70〜110時間 |
| テーマ素材（画像）と音 | 30〜50時間 |
| HP向けのWeb書き出しと計測 | 10〜20時間 |
| iOSの統合（広告SDK、ATT、保存、ビルド、実機検証） | 20〜40時間 |
| ストア準備（ポリシー、サポートページ、メタデータ、審査対応） | 30〜50時間 |
| 予備 | 20〜40時間 |
| **公開までの合計** | **190〜330時間** |
| 公開後のマーケティング（週5時間 × 10週） | 約50時間 |

3つの方式の比較（公開までの時間 + マーケティング50時間）：

| 方式 | 合計 | 312時間との関係 |
|---|---|---|
| React Native | 240〜380時間（中央値 約310時間） | 中央値でほぼ収まる。余裕はない |
| Swiftで作り直す | 約300〜480時間 | 下限でも収まらない |
| WebViewで包む | 約240〜370時間 | 収まるが、審査のリスクがある |

### 公開時期の感度

| 公開までの作業量 | 公開の時期 | 6月末までの期間 |
|---|---|---|
| 190時間（下限） | 3月中旬 | 約15週 |

## 現実性の評価

**「厳しめ。スコープを最小に絞り、スパイクで見積もりを較正することが前提なら、現実的」。** 週8時間だと、中央値の見積もりで、公開が5月中旬になる。最終期限にぎりぎりで、余裕がない。

| 項目 | 評価 | 根拠 |
|---|---|---|
| Web版を公開する（2〜3月上旬） | **現実的** | エンジンと試作がすでにある。素材の生成・置換・磨き込みが主な作業 |
| iOS版を5月中旬までに公開する | **条件付き。中央値でぎりぎり** | 上振れ（190時間）なら余裕、下振れ（330時間）なら間に合わない |
| 6月にL0-aを達成する | **公開が5月中旬までなら、見込みあり** | 必要なDAUは3〜20人程度と、低い水準。ただし、流入がゼロになる可能性は残る |

**確率を上げる方法：**

- **スコープを最小に保つ。** 上の前提以外の機能は、L0の後に回す
- **スパイクで、実際の作業速度を測る。** AIの活用で、コード部分の時間が見積もりより短くなる可能性がある。ゲート0で見積もりを再判定する
- **待ち時間のある作業を、先に始める。** Apple登録（承認まで2日〜1週間。経験談）、AdMobのアカウント、HPのポリシーページ

## リスク

| リスク | 内容 | 対策 |
|---|---|---|
| **スケジュール** | 中央値で最終期限にぎりぎり。スコープが増えると、すぐに間に合わなくなる | スコープを固定する。ゲート0で見積もりを再判定する |
| **審査（4.3など）** | 他のアプリに酷似したアプリや、飽和したカテゴリのアプリは、スパムとして却下されることがある。プライバシーの申告と実際の挙動が食い違っても却下される。審査は、90%以上が48時間以内に結果が出るとされる | テーマ・演出・手触りで差を出す。リジェクトが1回あっても間に合う余裕を持つ。プライバシーの申告は、広告SDKの実際の挙動と合わせる |
| **操作感** | React Nativeでのドラッグの手触りが、期待に届かない可能性がある | スパイクで、実機で確認する。足りなければSkiaを使う |
| **権利** | 素材とエンジンの置換が終わっていることが、HPの公開とiOSの公開の、どちらの条件にもなる | 公開前に、専門家への確認を入れる |
| **流入** | 公開しても、誰にも見つけてもらえない可能性がある | 自社HPからの導線、ストア検索のキーワード、30秒の動画を、公開前から準備する |
| **新規アプリの広告** | 新しいアプリは、公開直後に広告の配信が安定しないことがある | 判定の月の2週間前までに公開する |
