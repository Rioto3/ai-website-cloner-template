# magic-slide — L0達成計画（令和9年6月末まで）

## 目標

**L0（固定費の回収）を、令和9年（2027年）6月末までに達成する。** 今日（2026-09-29）から期限まで、約9か月（約39週）。

[SUCCESS_DEFINITION.md](SUCCESS_DEFINITION.md)の成長の曲線でいえば、A帯（敷居）を越えて、L0に届くところまでを、この計画の範囲とする。

## 進め方

1. **自社HP向けのWeb版を先に用意する。** コストが低く、直接の収益にはならないが、TubeClip全体として、ゲームの収益そのもの以外の意義がある。最終的には、責任を切り出してHPのプロジェクトにすることもできる。そのため、かなり安全に進められる
2. **完成した基盤を使って、次の投資を議論する。** iOSの開発者ライセンス（公開用）の取得、マーケティングとカスタマーサポートの体制へのリソース配分など。これらは、他の財源活動の観点でも重要になる
3. iOS版を公開し、広告で収益を立てて、L0に届ける

HPは、iOS版を出すときにも必要な基盤になる。App Storeには、プライバシーポリシーとサポートのURLが要る。また、広告のapp-ads.txtは、ストアに登録する開発者のWebサイトに置くと理解している（要確認）。

## L0の定義（案）

L0の達成を、次の2段階に分けて考える。

| 段階 | 内容 | 6月末までの見込み |
|---|---|---|
| **L0-a：収益が立つ** | AdMobの**確定額**で、月約7ドル（約1,070円）相当の収益が出る月ができる | 目標にする |
| **L0-b：現金で回収する** | 年会費相当（約1.3万円）が入金される | 6月末までは、ほぼ届かない |

L0-bが遅れるのは、AdMobの**支払い基準額**のため。日本円のアカウントでは8,000円（米ドルは100ドル）で、基準額に届くまで支払いは行われない。基準額は推定収益ではなく、確定額で判定される。L0水準の月約1,070円のペースなら、初回の入金まで約7〜8か月かかる。

**6月末までの達成条件は、L0-aにすることを提案する。**

## 作業量の概算

**私の見積もりで、データに基づく数字ではない。** 実際の確保時間や、AIの活用による圧縮の度合いで、大きく変わる。

| 作業 | 時間の目安 |
|---|---|
| Web版の完成（エンジンの仕上げ、素材、磨き込み） | 120〜200時間 |
| iOS版（Swiftで作り直す場合） | 100〜200時間 |
| iOS版（WebViewで包む場合） | 40〜60時間 |
| 広告・プライバシー・ストアの準備 | 40〜60時間 |
| 予備（リジェクト対応など） | 20〜40時間 |
| 公開後のマーケティング（週5時間 × 10週） | 約50時間 |
| **合計（Swiftの場合）** | **約330〜550時間** |
| **合計（WebViewの場合）** | **約270〜410時間** |

39週で割ると、**週に約7〜14時間の確保が要る**。

Web版には、土台がある。アーカイブのタグ`archive/mitsumori-ip-poc`に、クリーンルームのエンジン（盤面、重力、スコア、乱数）と、遊べる試作、音を出す仕組みが残っている。残りは、ブースター（ファイア・スライス・サンダー）、演出、素材の差し替え、磨き込み。

## 現実性の評価

**全体としては「条件付きで現実的。ただし余裕は小さい」。**

| 項目 | 評価 | 根拠 |
|---|---|---|
| Web版を2026年内に公開する | **現実的** | エンジンと試作がすでにある。素材の生成・置換・磨き込みが主な作業 |
| iOS版を4月中旬までに公開する | **条件付き** | 週10時間前後の確保が要る。Swiftで作り直す場合は、余裕が小さい。WebViewで包む場合は、工数は減るが、審査のリスクが増える（下記） |
| 6月末までにL0-aを達成する | **4月中旬までに公開できれば、見込みあり** | 必要なDAUは3〜20人程度と、低い水準。ただし、流入がゼロになる可能性は残る |
| 6月末までにL0-bを達成する | **非現実的** | 支払い基準額（8,000円）に届くまで、約7〜8か月かかる |

## リスク

| リスク | 内容 | 対策 |
|---|---|---|
| **スケジュール** | 「HP → 判断 → iOS → 審査」が順番につながっているため、どこかが遅れると全体が遅れる | ゲームのコアの仕様は、HP版とiOS版で共通にする。iOSの投資判断は、年会費（約1.3万円）が小さいので、早めてもコストは小さい |
| **審査（4.3など）** | 他のアプリに酷似したアプリや、飽和したカテゴリのアプリは、スパムとして却下されることがある。プライバシーの申告と実際の挙動が食い違っても却下される。審査の結果は、90%以上が48時間以内に出るとされる | テーマ・演出・手触りで差を出す。初回にリジェクトが1回あっても間に合う余裕を持たせる。プライバシーの申告は、広告SDKの実際の挙動と合わせる |
| **WebViewで包む案** | ウェブサイトを包んだだけのアプリは、最小機能の基準で却下される可能性がある。最新の状況は、確認できていない | 採る場合は、事前に確認する。端末の中に組み込んだゲームなら通りやすい、と理解しているが、要確認 |
| **権利** | 素材とエンジンの置換が終わっていることが、HPの公開とiOSの公開の、どちらの条件にもなる | 公開前に、専門家への確認を入れる |
| **流入** | 公開しても、誰にも見つけてもらえない可能性がある | 自社HPからの導線、ストア検索のキーワード、30秒の動画を、公開前から準備する |
| **Appleの登録** | 承認までの日数は、Appleが公開していない。個人の経験談では、2日〜1週間。4日間進まず、問い合わせた当日に承認された例がある | 2月上旬に申請する（1〜2週間の余裕を見る） |

## 短縮・分岐の選択肢

- **iOSの投資判断を早める。** 年会費は約1.3万円（Apple Developerアプリ経由で12,800円〜12,980円の報告がある）で、判断が遅れる方が、時間のコストとして大きい。HP版の公開前に申請すれば、実機での検証（TestFlight）を早く始められる
- **iOSの実装方式を、早めに決める。** Swiftで作り直す（工数は大きいが、審査に強い）か、WebViewで包む（工数は半分程度だが、審査のリスクを確認する必要がある）か
- **L0の定義を先に固定する。** L0-aとL0-bの区別を、この計画の前提にする

## 未確定の事項

- 週あたりに確保できる時間（上の工数の見積もりの前提）
- L0の定義（L0-aを6月末の目標にする案でよいか）
- iOSの実装方式（Swiftか、WebViewか）
- 権利の確認を、誰に、いつ依頼するか
- マーケティングとカスタマーサポートの体制（L0の段階では最小限とする想定。HPの問い合わせ窓口のみ）
