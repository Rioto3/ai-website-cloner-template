# magic-slide — As-Is / To-Be（プロデュース観点）

2026-09時点の整理。[docs/archive/2026-09-mitsumori-ip-poc/](../archive/2026-09-mitsumori-ip-poc/README.md)（前フェーズの反省）を受けた再スタート。

## As-Is（現状）

- 魔女IPの忠実クローンを内製化（vendor bundle.jsをそのまま使用、ゼロ外部依存で自社ホスティング）
- 広告・docomoポイント経済圏由来のUIを除去し、モバイルUXを調整済み
- Cloudflare Workers単体での配信基盤を確立（`npm run deploy` / `deploy:domain`）
- ゲーム単体でのマネタイズ手段は**ゼロ**。パブリッシュ基盤（ストア審査・課金・広告SDK等）も**ゼロ**
- 独自IPへの再テーマ化トライは失敗し、ロールバック済み（→ IPプロデュースは別スキルという学び）

## 意義の整理（なぜやる価値があるか）

1. **パズルゲームは非コアゲーマー層への親和性が高い** — セッションが短く中断・再開しやすい、学習コストが低い、デイリー動機付けと相性が良い
2. **AIによる解析で開発コストが劇的に下がる** — ゲームデザイン・バランス調整という最も時間のかかる工程を、既存タイトルの解析でスキップできる（実証済み）
3. **1本の価値ではなくパイプラインとしての価値** — 「調査→内製化→広告除去→単体デプロイ」の型は他タイトルにも横展開できる可能性
4. **技術ワークフローの実証** — AIエージェントでの複製〜内製化〜再構築が現実的に機能するという社内ナレッジ資産になる

## 市場性の論拠（パズルゲームは廃れない需要か）

- ぷよぷよ・テトリスは今も現役でeスポーツ化までしている。スイカゲームはデジタルコンテンツが飽和した現在でもバイラルした。**もし「パズルゲームのUX」が他のデジタルコンテンツに駆逐される性質のものなら、とっくに消えているはず** — 消えていない以上、構造的に持続する需要だと考えられる
- 需要の源泉は**ルールのシンプルさ**。RPG/アクションは独自性が強い分ルールが複雑。パズルゲームは「映画よりショート動画」に近い、忙しい文化にフィットするインスタントな需要に応える一方、シンプルだからこそやり込み要素も成立する — **一般層〜コアファンまで裾野が広い**
- したがって最初のペルソナは「画期的なゲームを求めるコアゲーマー」ではなく**一般層**。作り手としての目新しさは小さいが、事業側としては**ゲームエンジン自体に独自性が要らない**ため、読みやすく作りやすいというメリットがある
- 裏を返すと、**ゲームロジックは普遍的でコモディティ化している**ため、勝敗を分けるのはゲームロジックの外側 — パブリッシャーによるデジタルマーケティング、「正統タイトル感」「流行っている感」の演出、IP・ログインボーナスのような継続動機設計 — に強く依存する。パズルゲームはどれだけ頑張ってもUXがほぼ横並びになるからこそ、この部分の勝負になる

## To-Be（今回のスコープでの結論）

**本題は「ゲーム単体マネタイズ」。自社HP公開はその一つの実験台（低コストで仮説検証できる手段）であり、目的そのものではない。**

- ゲームロジック外側の難所（デジタルマーケティング、IP・キャラクター・効果音、ログインボーナス的な継続設計）は、本格的な商用展開では緻密に練る必要があるが、**自社HP掲載という「後ろ盾」がある間はそこまで頑張らなくていい** — 上限が「自社への興味喚起」で止まるため
- なので今フェーズでは、それらをプレースホルダー・既存の仕組みの流用でシンプルに済ませ、**まず無料公開を急ぐ**
- 一般公開・商用化に踏み出す段になったら、まさにこの「後回しにした部分」をより複雑化・精緻化する作業になる
- ランニングコストはほぼゼロ（ドメインは自社HPを流用、配信はCloudflare Workersでほぼ無料）— この低コスト構造自体が「まず動く」を正当化する

### 責任分界

- **本PJ（magic-slide）の責任範囲**：ゲームという土台そのものの提供、低コストでの配信・運用体制、商用化に向けた叩き台としての成立
- **ブランディング側PJの責任範囲**：IP・世界観・マーケティング設計などブランディングに関わる意思決定。本PJはそちらの意見を取り入れる側であり、自ら決定はしない

## 妥協点リスト（次フェーズへの申し送り）

今回「自社HPという後ろ盾があるうちは頑張らなくていい」という前提で、プレースホルダー/流用で済ませた箇所。一般公開・商用化に踏み出す際に、複雑化・精緻化が必要になる候補として明示しておく。

| 妥協した部分 | 現状 | 一般化する場合に必要なこと | 主な責任範囲 |
|---|---|---|---|
| IP・世界観 | 魔女IPをそのまま流用（独自IP化は前フェーズで失敗しロールバック済み） | 企画体系＋プロデュース観点からの再設計（[archive参照](../archive/2026-09-mitsumori-ip-poc/README.md)） | ブランディング側PJ |
| イラスト・効果音 | vendor資産をそのままミラー | 権利上、社外向け本格展開では差し替えが必要になる可能性。魅力的なキャラ・効果音の作り込み | ブランディング側PJ |
| ログインボーナス／デイリー動機付け | 未実装（該当UIごと削除済み） | パズルゲームの継続率を支える主要な企画要素。ゲームロジックが普遍的な分、ここが差別化の主戦場になる | ブランディング側PJ（本PJは実装受け皿） |
| デジタルマーケティング（「正統タイトル感」「流行ってる感」の演出） | 未着手 | パズルゲームはUXの差別化に限界があるため、勝敗を分ける中心的要素になる | ブランディング側PJ |
| マネタイズ導線 | ゼロ（広告もIAPも無し） | 収益化手段の選定（投げ銭、プレミアムスキン、広告あり/なし出し分け等） | 両PJ共同 |
| パブリッシュ基盤 | 無し（Cloudflare Workers単体配信のみ） | ストア配信・アカウント基盤・分析基盤などは未検討 | 本PJ |

## 次フェーズへの引き継ぎ事項

- 自社HPへの掲載自体は本ドキュメントのTo-Beで完結（別途、掲載先ページ・導線の設計が必要になり次第着手）
- 「同種案件の獲得」を狙うなら、ポートフォリオとしての見せ方（Before/After、技術的な見せ場）を別途整理する必要がある
- ゲーム単体マネタイズを一般公開レベルで本格化する場合、上記の妥協点リスト（特にブランディング側PJの責任範囲）がそのままスコープ候補になる。本PJはあくまで土台・低コスト運用の提供責任を負い、ブランディングに関わる意思決定はブランディング側PJの意見を取り入れる形とする
