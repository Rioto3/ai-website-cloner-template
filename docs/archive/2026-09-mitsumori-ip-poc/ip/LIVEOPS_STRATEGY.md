# ミツモリ村 — 運営戦略（ライブオプス）

## 1. 事業前提

- 本体は**ブラウザHTML5・縦画面・1セッション3〜5分**のカジュアルパズル。
- 収益モデルは配信面で二択（両対応できる設計にする）:
  - A) ポータル型（旧作と同型）: リワード広告+ポイント連携。シェルの
    postMessageプロトコル（start/end/save/getdata/rewardad）を既に自前実装済みで、
    どのポータルにも同型で差し込める。
  - B) 自社配信型: 広告SDK+シーズンパス（軽課金）。エンジンが独立しているので移植容易。

## 2. コアループと計測

```
きょうの出荷ノルマ(デイリー目標) → プレイ → 壺/金のしずく → ハニーコイン → 型ガチャ(収集)
                ↑____________________ シーズンイベントが味変 ____________________↑
```

| KPI | 目標値（カジュアルパズル基準） | 対応する設計 |
|---|---|---|
| D1リテンション | 35%+ | デイリーノルマ+初回ガチャ確定演出 |
| D7 | 15%+ | 週替わり「村のおしごと」ミッション |
| 平均セッション | 3分 / 日3回 | 1プレイの長さは難易度カーブ（23段階）で既に最適化済み |
| 広告視聴率 | 30%+ | 「おてつだいを呼ぶ」(コンティニュー)と「型ガチャおかわり」の2面のみ。広告面を増やさない |

- 計測イベント: `start / end(score) / continue / reward_view / gacha / skin_equip` —
  既存プロトコルの `execute` に自然対応。

## 3. コンテンツカレンダー（年間）

| 季節 | イベント | ゲーム内変化 | 目玉 |
|---|---|---|---|
| 春 | さくら蜜まつり | 背景・ゼリーが桜色/花びら粒子 | 限定型「さくらモールド」 |
| 夏 | ソーダ祭り | ソーダゼリー出現率UP・炭酸SE | ビィの麦わら帽スキン |
| 秋 | どんぐり収穫祭 | **カラどんが主役**（石ブロックがボーナス化する逆転ルール） | カラどんぬいぐるみ柄 |
| 冬 | 雪蜜のよる | 夜背景+雪、BGMオルゴールアレンジ | 金のしずく2倍週間 |

- イベントは**ルールを足さず「係数と見た目」だけ変える**（config.jsonの
  level/holl/typeテーブル差し替えで実現可能な範囲に限定）→ 運営コスト最小化。

## 4. 収集システム（型ガチャ）の運用

- 既存設計の20スキン×レア3段階（12/4/4、確率6.7/3.75/1.25%）をそのまま「ゼリーの型」に。
- 天井: ハニーコイン直接購入（skinPrice=2000）が実質天井として機能済み。
- シーズンごとに+4型（うちレア1）。**排出率は公開**（信頼性=IPブランドの一部）。

## 5. コミュニティ / IP展開

- 週1の「ミツモリ村だより」（4コマ・X/Instagram）: ゲーム外接点でキャラ人気を育てる。
  ネタはゲーム内演出と連動（例: カラどん回の週はゲーム内でカラどん出現率UP）。
- ファンアートタグ `#ミツモリ村`。キャラ利用ガイドライン（非商用OK）を早期公開。
- グッズ第一弾はカラどん（「困りごとが一番かわいい」law of mascots）。

## 6. リスクと手当て

| リスク | 手当て |
|---|---|
| 既存作との視覚的類似の指摘 | 素材は全て新規SVG（ART_DIRECTION §5）。メカニクスはルールでありIP非依存 |
| イベントで難易度が壊れる | config差し替えは smoke テスト（`npm run game:test`）をCIゲートにする |
| 広告在庫枯渇（ポータル型） | 広告失敗時は無償リトライ1回/日のフォールバック（fail_callback経路は実装済み） |
| 低速端末 | パーティクル上限12・DOM/SVGレンダラは軽量。実測60fpsをリリース基準に |
