# アーカイブ: ミツモリ村IP独自化 PoC（2026-09時点でロールバック）

## これは何か

本PJは「魔女」パズルゲームの忠実クローン（内製化）からスタートし、その後2段階の独自化を
試みた：

1. **Level 2: 独自エンジン化** — 模倣元の `bundle.js`（難読化されたPixiJS実装）に依存せず、
   クリーンルームでゲームロジックを再実装（`src/game/engine/`）。設計スペックは
   [`game/GAME_DESIGN.md`](game/GAME_DESIGN.md) にあった。
2. **オリジナルIP「ミツモリ村」** — エンジンはそのまま（メカニクスは変えない前提）で、
   世界観・キャラクター・ブランドを新しいIPとして再構築する試み。詳細は
   [`ip/IP_BIBLE.md`](ip/IP_BIBLE.md) ほか `ip/` 配下の各ドキュメント。

このアーカイブは、2026-09にコミット `ac156ec`（魔女IPの忠実クローン、Level 1完了時点）へ
`git reset --hard` でロールバックする直前に、当時のドキュメント資産を保存したもの。
コード全体（`src/game/engine/*`, `src/components/mitsumori/*` 含む）は
git タグ `archive/mitsumori-ip-poc` から参照できる。

```bash
git show archive/mitsumori-ip-poc:src/game/engine/game.ts
git diff ac156ec archive/mitsumori-ip-poc --stat
```

## 結論（主観評価）

- ゲーム性がかなり失われた。
- 独自性（ミツモリ村のテーマ）自体もあまり面白いと感じられなかった。
- **ただしこれは「IPは簡単に作れるのでは？」という独自プロデュースのPoCとしての試行でもあり、
  その観点では valuable な負の結果**: 少なくとも、プロデュース的な観点からの再出発が
  必要という結論に至った。IPは（デザイン層の差し替えだけでは）簡単には作れない。

## 学び（次に活かすためのメモ）

- **独自性の着地点を事前に定めていなかった**。「エンジン/メカニクスは変えず、テーマ層だけ
  差し替える」というスコープを [`ip/IP_BIBLE.md`](ip/IP_BIBLE.md) の「メカニクス→世界観の
  翻訳表」で最初から固定してしまっていた。これは模倣元の独自性がゲームエンジン側に
  埋め込まれていて分解できなかったため、と推測される。結果として新しいオリジナリティも
  表層の1:1置換（宝石→蜜ゼリー、魔女→こぐま、岩→カラどん、のような対応表）に留まり、
  メカニクスと有機的に結びつかなかった。
- 独自性の**期待値**（メカニクスそのものに新規性を求めるのか、テーマ層だけで良しとするのか）
  を最初に言語化しておくべきだった。今回はそれをしないままトライして、事後に「なんとなく
  失敗した」という感覚だけが残った。
- IPを新規に立てるなら、デザイン/エンジニアリングだけでなくプロデュース（世界観の背骨となる
  コア体験は何か、既存メカニクスとどう緊張関係を作るか、等）の観点からの検討が要る。

## ロールバック後の位置づけ

このロールバック時点で、本PJは魔女IPの忠実クローン（`ac156ec` 相当）に戻り、テンプレート
系コンテンツを切り離した上で、検証環境のUX調整・Cloudflare Workers単体デプロイの確立を
進めている。プロデュース観点の as-is/to-be 整理は改めて別途行う（このロールバック作業では
着手しない）。
